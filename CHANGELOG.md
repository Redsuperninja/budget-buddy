# Changelog

## Unreleased
- Safer key checks (#26): if the `key-fingerprint` file in your data folder is lost, Budget Buddy no longer makes a new key over your existing data, and it tests a key or recovery phrase on the data itself before accepting it, so a phrase from another folder can't be saved by mistake.
- More of your data is encrypted (#28, step 1): bank names, employer names, charity names and shop names on receipts are now stored encrypted. Existing entries are encrypted the next time Budget Buddy starts (a copy of the old file is kept, as before). Amounts, dates, transaction descriptions and account names are still readable in the data folder.
- More of your data is encrypted (#28, step 1): bank names, employer names, charity names and shop names on receipts are now stored encrypted. Existing entries are encrypted the next time Budget Buddy starts (the copy of your old data that Budget Buddy keeps before an update, like `budget.db.bak-0027`, still holds those names as plain text; Budget Buddy lists it so you can delete it once everything works). Amounts, dates, transaction descriptions and account names are still readable in the data folder.
- Behind the scenes (#21): the phone app no longer pulls in an old `uuid` through the Expo build tools (one advisory fixed). The other npm advisories stay open because fixing them needs a major Expo or Jest upgrade; none can be triggered by using the app except a rare crafted-link hang (see issue #21).
- Behind the scenes (#21): the phone app now uses a fixed `decode-uri-component` (a crafted `budgetbuddy://` link could make the app hang) and a fixed `uuid` in the Expo build tools. The remaining npm advisories sit in build and test tools and need a major Expo or Jest upgrade to clear; see issue #21.

The other npm advisories stay open because fixing them needs a major Expo or Jest upgrade; none can be triggered by using the app except a rare crafted-link hang (see issue #21).
- Behind the scenes (#21): the phone app no longer pulls in an old `uuid` through the Expo build tools. - For developers (#28, step 2): whole-database encryption was tried out; ADR-0014 proposes SQLCipher (`sqlcipher3`) on top of today's field encryption. Nothing changes in the app yet.
- For developers: the server tests run about twice as fast. The migrated database is built once per test session and each test starts from a copy; tests of migrations, keys, first run and backups still run every migration (`@pytest.mark.real_migrations`, see `docs/dev/testing.md`).
- Faster dashboard: the browser now keeps the dashboard's files and only checks that they haven't changed (a repeat visit to Home goes from 82 downloaded files, about 236 KB, to 41 quick "unchanged" checks with nothing downloaded), and each page's code loads only when you open it. Transactions no longer re-fetches categories, lots and sales on every search. Updates still show up right away.
- Smaller Windows download: about 38 MB instead of about 55 MB, and about 76 MB installed instead of about 104 MB (sizes as Windows shows them). The apps no longer carry parts they never use (picture formats, a code highlighter, setup tools), and each release is built in a fresh, empty Python setup from new lock files (`requirements-package.txt`), so developer tools and old packages can't sneak in.
- Spending trend and sweeps load faster with many transactions (checked with 20,000 made-up ones): the trend adds up net worth in one pass, and the sweep, trade, dividend and transfer finders skip the notes and linked rows they never read. Results are unchanged. For developers: `scripts/dev/bench_reports.py` times them.
- Safer key storage (#27): Budget Buddy keeps its encryption key only in a real password vault (Windows Credential Manager, macOS Keychain, GNOME Keyring or KWallet). On Linux, a keyring that saves passwords in a file (like `keyrings.alt`) is now refused with a clear message instead of being used.
- Behind the scenes (#6, part 2): the Home Base and desktop app install exact versions from lock files with hashes (`requirements.txt`, `requirements-dev.txt`; ADR-0013), on every computer and in CI, so a changed or hijacked package fails the install instead of running. Developers: after changing a `pyproject.toml`, run `scripts/dev/lock_dependencies.py`.
- Behind the scenes (#6, part 1): the Home Base installs fewer packages (plain `uvicorn`, without extras it never used); GitHub Actions are pinned to exact commits; Dependabot opens weekly update PRs. Lock files with hashes come next.

- Auto-sort rules: tell Budget Buddy that a description containing some text (like "GROCERY MART") belongs in a category. New bank-file rows and transactions added without a category are sorted automatically, the longest matching text wins, a category you picked is never changed, and a "Sort transactions now" button sorts older transactions that have no category yet.

- Project layout: the web dashboard now lives in its own top-level `dashboard/` folder, separate from the server and the phone app. The server serves it from a fixed list of files (or runs API-only without it), and it has its own tests and checks (ADR-0005).

- Phone sync on the Home Base: a paired phone can now download a budget snapshot (this month's budget, recent transactions, accounts, tax totals), upload receipt photos, and report that it finished syncing. Everything is encrypted and each request works only once; removed phones are refused immediately. Photos are checked (JPEG, 3 MB, size in pixels) before they are saved encrypted, and a retried upload never creates a second copy.

- Encryption at rest: account numbers, notes, and receipt file names are encrypted in the database, receipt photos can be saved encrypted, the key lives in Windows Credential Manager (or the macOS/Linux equivalent), and a recovery phrase lets you get your data back if that key is lost (ADR-0003).
- Accounts + transactions API for the computer-side dashboard (`/api/local/...`, this computer only): add, edit, and remove accounts and transactions, see account balances, filter and page through transactions, and link transfers between your own accounts. Errors come back as plain-English messages. Other websites open in your browser can't reach it (Host and Origin checks), every route except the phone's is this-computer-only by default, search text stays out of the logs, and transfers, refunds and opening balances follow fixed rules so they never turn into surprise income or spending.
- Phone Home dashboard: this month's income, spending, what's left, and savings rate; Needs / Wants / Savings bars you can tap to see categories; recent activity; and a Taxes summary. Shows clearly labeled sample data until the phone is connected.
- Categories and monthly summary for the computer-side dashboard: list, add, rename, and set a monthly budget for categories, plus a per-month view of income, spending, and savings that leaves out transfers and balance adjustments (like opening balances) and nets refunds against spending. Budgets apply to every month. Changing one also changes what past months show.
- Bank CSV import: load your bank's CSV download into an account. Budget Buddy spots the date, description and amount columns (or separate money-out/money-in columns), copes with `$` signs, commas, `(12.34)` negatives, different date styles, header lines and file encodings, and lets you flip the signs for credit cards. You see a preview first, re-importing an overlapping statement skips rows already there, and the column choices can be saved per account so next time is one click. Files are capped at 5 MB / 10,000 rows, and nothing from the file is written to the logs.
- Paychecks API (`/api/local/paychecks`, this computer only): enter, edit, and remove paychecks with every pay-stub line (taxes, before-tax and after-tax deductions), checked to add up to the cent; link a paycheck to its bank deposit without counting the money twice; and see year-to-date totals with a check for too much Social Security withheld. See `docs/guide/paychecks.md`.
- Receipts API for the computer-side dashboard (`/api/local/receipts`, this computer only): add, edit, and remove receipts (shop, date, total, category, linked transaction, encrypted notes) and attach a photo. Photos must really be JPEG, PNG or HEIC (checked from the file itself) and at most 3 MB; location and camera details are removed from JPEG and PNG photos; photos are encrypted on disk and deleted along with their receipt. Reading text from photos (OCR) comes later.
- Charitable donations: add, edit, and remove cash and goods donations (optionally linked to a receipt), and see a yearly summary that totals your gifts and tells you what proof to keep, such as a written acknowledgment for gifts of $250 or more, Form 8283 when goods add up to more than $500, and an appraisal for items worth more than $5,000. The amounts come from each tax year's data file, and the summary is an estimate, not tax advice.
- Phone pairing screen: scan the code from your computer (or type it in) to connect, with plain-English help if something goes wrong; Settings has a Connect button, and the phone's keys are kept in its secure storage.
- Phone pairing on the computer side: "Pair a phone" makes a one-time code (QR or pasteable text) that expires after 10 minutes and works once, the phone and computer agree on a private key without it ever appearing in the QR, paired phones are listed, and Remove stops a phone from working right away.
- Stocks: record purchases (symbol, date, shares, total cost with fees) and sales (shares and money received after fees) at `/api/local/stocks/...`. Sales use your oldest shares first (FIFO), including part of a purchase; each part is marked short term (held one year or less) or long term, counting from the day after you bought; possible wash sales are flagged without changing the numbers; and a yearly summary totals short- and long-term gains. Selling more shares than you owned gets a plain-English error, and every result is labeled an estimate, not tax advice.

Plus a tester guide (`docs/testing/`), a feedback issue template, and a milestone plan in the roadmap.
